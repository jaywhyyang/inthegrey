공개 대시보드: https://jaywhyyang.github.io/inthegrey/

## 이 폴더만으로 됩니다

밴드 수치를 포함해 페이지 생성에 필요한 건 전부 이 리포 안에 있습니다.
그린랜드2 폴더가 없어도 `python build_ig.py` 가 동작합니다.

```
kobis_realtime.py   → inthegrey_hourly.csv   (실시간 예매 스냅샷 수집)
build_ig.py         → index.html             (페이지 생성)
megabox_solo_band.json                        (흥행 기대 밴드 — 읽기 전용)
```

시간별 OS 작업이 위 두 단계를 돌리고 `index.html` 을 커밋·푸시합니다.

## 손대면 안 되는 것

**`build_ig.py` 에 밴드 숫자를 직접 적지 마세요.**

`BAND_LO` 등 상수는 교환 파일을 못 읽을 때만 쓰는 폴백입니다. 실제 값은
`megabox_solo_band.json` 에서 매 빌드마다 다시 읽습니다(`load_band()`).
손으로 옮겨 적으면, comp 가 갱신될 때 반드시 드리프트합니다 — 실제로 한 번
그렇게 어긋난 적이 있습니다(임의 중심값 3.5만).

밴드가 교환 파일에서 읽혔을 때만 페이지 하단에 `comp N편 · YYYY-MM-DD 기준` 이
찍힙니다. 그 표기가 없으면 폴백으로 돌고 있다는 뜻입니다.

## 밴드를 갱신해야 할 때

comp 가 바뀌는 경우입니다 — 대표적으로 **워페어 종영**(현재 상영 중이라 최종이
아닙니다). 그때만 그린랜드2 폴더에서 분석을 다시 돌립니다.

```bash
cd "../그린랜드2"
python kobis_multichain.py      # 체인별 편성 (신규 주차만, 이어받기)
python kobis_all_daily.py        # 관객·좌석 (신규 날짜만, 이어받기)
python build_megabox_solo.py     # comp 산출 → 교환 파일 + 이 리포 사본까지 자동 갱신
```

끝나면 이 폴더의 `megabox_solo_band.json` 이 갱신돼 있습니다. 커밋하세요.

## megabox_solo_band.json 에 든 것

| 키 | 내용 |
|---|---|
| `observed` | comp 실측 통계만. 판단 안 섞임 |
| `scenario` | 표시용 밴드. **`assumptions` 를 반드시 같이 읽을 것** — 개봉일 좌석 5만석 가정 위의 값 |
| `model` | `ln(최종) = a + b·ln(개봉일관객)`. 개봉일 관객이 찍히면 직접 재예측 가능 |
| `pacing` | 개봉 N일차 누적 비중 중앙값. D3 가 0.40 을 넘길 기세면 즉시소진형(2만대), 0.30 안팎이면 롱런형 |
| `comps` | 근거 작품 목록 |
| `caveats` | 상영 중 작품 포함 여부 등 자동 경고 |

세그먼트 정의(실사 외화 × 메가박스 150관 이상 × 일본 제외)를 바꾸려면
그린랜드2의 `emit_band.py` 상단 상수를 고칩니다.

## 공개 표기 원칙

페이지 문구와 수치는 **수집 데이터와 공개 정보로부터의 유추만** 씁니다.
배급사 내부 대화에서 나온 정보는 넣지 않습니다(사이트/내부 이중관리).

예외적으로 프로모 분해(`SHOW_ORGANIC`)는 2026-08-28 사용자 결정으로 공개합니다.
누적 예매가 KOBIS 공개 데이터라, 실예매를 표시하면 빼기로 프로모 집행 장수가
역산된다는 점을 확인한 뒤 내린 결정입니다. 되돌리려면 상수만 `False` 로 바꾸면 됩니다.
